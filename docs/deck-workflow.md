# 덱 워크플로 (트랙 B) — 원문 → 이미지 슬라이드 PPT

SKILL.md 트랙 B에서 여기로 온다. 문서·보고서·논문·강의노트를 **시각적으로 통일된 이미지 슬라이드 덱**으로 만든다.

> **먼저 확인할 것**: 사용자가 나중에 글자를 고쳐야 하는 자료(정부 R&D 평가자료, 반복 수정되는 사업계획서 등)라면 이 트랙이 아니라 `pptx` 스킬이 맞다. 이 트랙의 산출물은 이미지라 텍스트 편집이 불가능하다. 애매하면 착수 전에 한 번 묻는다.

## 산출물 구조

```
gpt-image/<덱이름>/
├── slide_01.png … slide_NN.png   # 조립 대상 (이 이름 규칙이어야 인식된다)
├── sample_slide.png              # 샘플 (slide_NN 아니므로 조립에서 자동 제외)
├── outline.md                    # 확정된 아웃라인
├── speech.md                     # 발표노트
└── <덱이름>.pptx                 # 최종
```

## 단계

### 1. 원문 파악
주제·청중·목적·분량 제약을 뽑는다. 원문이 길면 핵심 논지와 근거를 먼저 정리한다.

### 2. 아웃라인 확정 — **승인 없이 다음으로 가지 않는다**
장수, 각 장의 역할(표지/목차/문제/해법/근거/사례/정리), 제목, 핵심 문구 3개 이내를 표로 제시하고 승인받는다.

이 단계를 건너뛰면 나중에 전량 재생성이 된다. 장당 1~2분 + 구독 한도가 걸린 작업이라 되돌리는 비용이 크다. 확정본을 `outline.md`로 저장한다.

발표 시간이 주어졌다면 1장 = 1~2분으로 환산해 장수를 제안한다.

### 3. 스타일 선택
`references/ppt-styles.md`의 12종에서 고르게 한다. 사용자가 브랜드 색·폰트 톤을 주면 그것을 우선한다.

**선택한 스타일의 프롬프트 조각을 모든 장에 동일하게 붙인다.** 장마다 스타일 어휘가 흔들리면 덱이 따로 논다.

### 4. 샘플 1장 — **승인 없이 전체로 가지 않는다**
가장 대표적인 장(보통 표지 또는 본문 첫 장) 하나를 `sample_slide.png`로 생성한다.
Read로 열어 확인시키고 승인받는다. 여기서 스타일·색·글자 처리를 확정한다.

### 5. 전체 생성
SKILL.md 4단계를 장별로 **순차** 실행한다 (동시 생성 금지 — 정책훅 우회가 깨진다).

- **승인된 샘플을 레퍼런스로 첨부한다.** 스타일 조각을 텍스트로만 반복하면 장마다 톤이 흔들린다. 4단계에서 확정한 `sample_slide.png`를 매 장 생성에 `-i`로 같이 넘기고, 프롬프트에 한 줄 박는다:

  ```
  -i "<sample_slide.png 절대경로>"
  ...
  Match the visual style, palette, and layout grammar of the attached reference image.
  Do NOT copy its text or specific content — only its art direction.
  ```

  텍스트 조각(3단계)과 **병행**한다. 어느 한쪽만으로는 부족하다.
- 파일명은 `slide_01.png`, `slide_02.png` … (2자리 0채움). **번호를 건너뛰지 않는다** — 실패한 장이 있으면 그 번호를 비워두지 말고 재생성하거나 사용자에게 알린다. 조립 스크립트가 결번을 감지하면 중단한다.
- **Aspect ratio: 16:9 고정**
- **해상도는 `1792x1024`** — 16:9에서 화이트리스트가 허용하는 유일한 값이다 (SKILL.md 4단계 표). "2K 권장"이라는 옛 표기는 16:9에 해당 값이 없어 폐기했다.
- 그래서 **덱은 잔글씨가 뭉개지기 쉽다.** 한글 정확도를 올리는 레버인 `2048` 캔버스를 16:9에서는 쓸 수 없기 때문이다. 대응은 둘 중 하나:
  - 장당 문구를 적게 가져간다 (짧은 카피, 큰 글씨).
  - **글자가 정확해야 하면 트랙 D로 간다** — 배경만 생성하고 글자는 폰트로 얹는다 (SKILL.md 트랙 D). 오탈자가 원천적으로 없고, `.pptx`를 편집 가능본으로 낼 수도 있다.
- 진행 상황을 `n/전체`로 보고한다.
- 실패한 장은 성공분을 지키고 원인을 보고한 뒤 재시도 여부를 묻는다.

### 6. 품질 점검
전 장을 Read로 열어 확인한다:
- 글자 오탈자·깨짐 (한글은 특히)
- 장간 스타일·색·여백 일관성
- 잘림, 빈 영역, 중복 요소

문제가 있으면 SKILL.md 6~7단계(리뷰 팝업 → 붓/핀 수리 또는 재생성)로 고친다. 글자만 틀린 경우는 재생성하지 말고 **붓 수리**가 훨씬 싸다 (쿼터 0, 1초).

### 7. 발표노트
`speech.md`에 장별로 쓴다. 헤딩이 페이지를 가르며 아래 형식을 모두 인식한다:

```markdown
## Slide 1: 표지
여기에 1장 멘트.

## 2장: 문제 제기
여기에 2장 멘트.
```

### 8. 조립

```bash
python "$HOME/.claude/skills/gpt-ppt-image/scripts/assemble_ppt.py" \
  gpt-image/<덱이름> -o gpt-image/<덱이름>/<덱이름>.pptx \
  --notes gpt-image/<덱이름>/speech.md
```

- `slide_NN.png`만 페이지 번호순으로 들어간다. 샘플·참고 이미지는 자동 제외된다.
- 2MB 초과 이미지는 JPEG로 압축된다 (pptx 비대화 방지).
- 의존성: `pip install python-pptx Pillow`

### 9. 검증 후 보고
생성된 .pptx를 **실제로 열어** 장수·비율·노트를 확인한다. 그다음 보고에 포함할 것:
- 최종 경로, 장수, 사용한 스타일
- **이 덱은 이미지 슬라이드라 텍스트 편집이 불가능하다는 사실**
- 남은 한계(뭉개진 글자 등)가 있으면 숨기지 말고 명시

최종 .pptx 경로를 사용자에게 알린다.
